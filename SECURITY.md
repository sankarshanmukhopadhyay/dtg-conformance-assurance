# Security Policy

Security and assurance-integrity fixes are applied to current `main` and the latest supported release/method line identified by repository status metadata. Older versions should be treated as unsupported unless a maintainer explicitly states otherwise.

Do not disclose undisclosed vulnerabilities in public issues. Use GitHub private vulnerability reporting when available, or contact the repository maintainer through a private channel identified on the maintainer profile.

Include the affected revision/version, reproduction steps, impact, affected conformance/decision evidence, and any known mitigation.

DCAS owns its evaluation method and decision-receipt semantics; it does not acquire authority over the domain requirements it evaluates. A defect that can alter PASS/FAIL/INDETERMINATE results or accepted evidence must identify potentially invalidated receipts/evidence and must not silently preserve a stale PASS.
