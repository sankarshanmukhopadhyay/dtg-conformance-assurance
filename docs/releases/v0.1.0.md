# v0.1.0 — Adopter-grade DCAS baseline

This is the first tagged release of **DTG Conformance & Assurance (DCAS)**.

## What this release delivers

### 1) A clear adoption front door
- Role-based onboarding (`docs/start-here.md`, `docs/roles/`)
- Repository map and FAQ (`docs/repo-map.md`, `docs/FAQ.md`)
- Updated README routing for first-time adopters

### 2) A repeatable evaluation method (“DCAS Evaluate”)
- Versioned method package (`DCAS_METHOD_VERSION`, `docs/dcas-evaluate/`)
- Report template, scoring + confidence rubric, and evidence checklist template

### 3) Minimum viable traceability spine (machine-readable)
- Populated catalogs:
  - controls: `controls/control_catalog.csv`
  - evidence: `controls/evidence_catalog.csv`
  - tests: `controls/test_suites.csv`
- Risk → CO mapping: `risk/mapping/risk_to_control_objectives.csv`
- Generated coverage snapshot: `risk/reports/coverage_summary.md`

### 4) Cleaner exports and tooling
- Regenerated and normalized `risk/exports/risk_assessment.csv`
- Updated export/validation scripts in `tools/`
- Repo hygiene improvements (`.gitignore`, removed stray files)

## Compatibility and expectations

- DCAS remains **implementation-neutral**: no protocol, DID method, ledger, or product is mandated.
- Catalogs and IDs are stable within the release; avoid renumbering without a release.

See `docs/roadmap.md` for the next increment (automation + worked examples + deeper control granularity).
